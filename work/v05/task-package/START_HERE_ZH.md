# 把 Syna v0.5 任务交给 Claude Code

这是任务提示词包，不是 Syna v0.5 源码。主提示词已经包含最新需求、裁剪结果、历史回归反例和交付门槛，不依赖 Claude Code 记得这段聊天。

## 最短启动路径

1. 在本机进入真实的 Syna 工作区。建议以你已经拿到的 `syna-v0.4.0-source` 为代码基线，保留 git 状态和自己的未提交改动。不要误用 `synajs/syna` 的早期 main 当成 v0.4 源码。
2. 把本包中的 `SYNA_V05_EXECUTION_PROMPT.md` 和 `SYNA_V05_GOAL.txt` 复制到该工作区根目录。其余文件是使用说明和研究出处，不必加入 npm 发布包。
3. 使用你获准使用的模型和权限模式启动 Claude Code。按当前官方文档，可以使用以下命令；模型/effort/权限可用性仍以本机版本与账户为准：

```sh
claude --version
claude --model fable --effort xhigh
```

4. 在 Claude Code 的输入框中粘贴 `SYNA_V05_GOAL.txt` 的全部内容。它以 `/goal` 开头，会立即开始任务，不需要先让 Claude 另外写一轮泛泛计划。

本提示词已经授权正常本地开发和隔离测试，不授权强推、npm 发布、线上部署或使用生产数据库。`/goal` 不会绕过权限提示。先确认测试 PostgreSQL 可用，会避免长任务在最后卡在必须的真实后端验收上。

## 为什么不把全部正文塞进 /goal

官方 goal 条件长度上限是 4,000 字符；本包把完整任务放入文件，把可检查的结束条件留在 goal。评估器不能独立读文件或执行测试，所以必须让实施会话把真实命令结果展示出来。

`/goal` 可以因条件满足而结束，也可能因被判定无法满足或某些需人工处理的错误而被清除；停止并不等于代码交付成功。只认任务规定的 COMPLETE 证据，BLOCKED 必须被明确区分。

本包没有为你安装一个永远拒绝退出的 Stop hook，也没有修改任何 `.claude/settings.json`。模型裁判不能替代实际验收脚本和独立审计。

## 模型与 effort

当前官方文档中，`fable` 别名对应 Fable 5.1，要求 Claude Code v2.1.255 或更高；账户、组织或第三方 provider 可能限制可用模型。若本机不支持，使用 `/model` 中实际可用的高能力代码模型，不要伪装自己在使用 Fable。

本任务推荐 `xhigh` 配合独立审计。`/effort max` 可提高推理投入，但官方也提示可能收益递减或过度思考；它不是“无 bug”开关。

Fable 在部分账户上会使用额外 usage credits；先看交互界面的计费提示。不要把“发挥实力”误解为自动授权未知费用。本指南优先采用交互模式，不提供绕过权限或隐藏计费确认的启动方式。

## 并行方式

默认用主会话负责内核和整合，以原生 subagents 分担应用、对抗审计、归档与性能核验。主提示词限制同文件并发修改，也要求 worktree核对真实基线。

Agent teams 是可选实验功能，不必为本任务开启。只有其已经可用、且确实存在可独立推进的任务时才采用；使用更多 agent 不是验收条件。

## 进度、中断与恢复

会话中输入 `/goal` 查看状态。需要停止目标时使用 `/goal clear`，需要打断当前执行时按 Ctrl+C。工作进度保存于 `work/v05/STATE.md`。

恢复同一会话可使用：

```sh
claude --continue
# 或选择历史会话
claude --resume
```

恢复后确认 goal 是否仍然活跃、工作区是否正确，必要时重新粘贴 goal 文件。不要用 `/clear` 假装已经保留全部约束；恢复时让 Claude 重新读取主任务书和状态账本。

真实外部阻塞时，允许记录 BLOCKED 并暂停；不能把它包装成 COMPLETE。资源权限恢复后从账本和复现命令继续。

## /goal 不可用时

先检查本机版本、工作区信任和 hooks 的组织策略。不要绕过组织限制。也可以在正常允许编辑和运行工具的会话里直接粘贴以下指令；主任务书依然有效，只是失去 goal 的自动多回合续行：

```text
完整读取当前工作区的 SYNA_V05_EXECUTION_PROMPT.md。按其中范围实施 Syna v0.5 + Hyla-mini，而不是只写计划。先完成真实应用纵向用例，再修复内核并执行独立复核。以 node scripts/verify-v05.mjs --release 的真实结果、归档重新构建和对应证据判断完成；外部阻塞如实记录，不虚构 PASS。
```

## 最后应当拿到什么

不是“新的设计文档”而是包含真实源码、Hyla-mini、测试、锁文件和重跑命令的源码归档，以及独立安装包、真实PG/文件系统四格测试结果、工作集/性能原始数据、迁移说明和审计记录。源码归档不应夹带 node_modules，也不能依赖工作目录中的旧 dist 才能通过测试。

本包的 SHA256SUMS 只验证提示词文件的一致性，不代表 Syna 实现已经通过任何测试。
