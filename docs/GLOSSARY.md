# Glossary (v0.8)

The vocabulary of `syna` from 0.8.0 on, one term per concept, with the Chinese rendering used in the Chinese documents. 0.8.0 is the last rename before 1.0 (`docs/API_STABILITY.md`): these are the words the public names are built from, and a later addition uses them the same way (naming guideline 6). Where a term has a public name next to it, the name is given in code font.

| Term | 中文 | Meaning | Public names |
|---|---|---|---|
| Runtime | 运行时 | The finite, closed, immutable world of definitions a program creates once: the admission set, the private closures, the policies, the limits. It plans and materializes; it holds no instance of its own. | `Runtime`, `createRuntime()` |
| Env | 环境 | One world created by one Entry invocation: an immutable topology of slots, a state (`activating → ready → disposing → disposed`), a parent or none. Envs form a single-parent forest. | `Env`, `EnvState`, `env.enter()` / `run()` / `derive()` / `anchor()` |
| Entry | 入口 | The declaration of how an Env is created: what it requires, which Inputs and Bindings it takes, what it reuses. `define.entry()` returns an `Entry`; `EntryDefinition` is the record it is built from. | `Entry`, `EntryDefinition`, `EntryOptions` |
| Service, Family, Revision | 服务、家族、修订 | A Service is a definition with a setup. Its Family is its stable identity across versions (`family.id`); a Revision is one exact version of it (`revision.id` = `family@version`). | `ServiceRevision`, `ServiceFamily`, `ServiceRange` |
| Contract, Input, Binding | 契约、输入、绑定 | The three lifecycle-free descriptors: a nominal API shape with implementations; an external fact provided at an Entry; a named, inherited implementation choice. | `Contract`, `Input`, `Binding` |
| Implementation reference | 实现引用 | The JSON-safe record of a Binding choice or a catalog lookup: `{ kind: 'implementation-ref', contractId, familyId, range }`. One serialized shape; anything else is refused. | `ImplementationRef`, `Binding.to()` / `parse()` |
| Implementation record | 实现记录 | What the catalog says about one revision of one Contract: family, version, eagerness, both metadata levels and the reference that names it. | `ImplementationRecord`, `catalog.implementations()` / `resolve()` / `revisions(family)` |
| Candidate | 候选 | One member of a `C.all` collection in the current Env: a real node, loadable through its collection, identified by a `CandidateRef` that belongs to that collection alone. | `ImplementationCandidate`, `CandidateRef`, `ImplementationSet` |
| Slot | 槽位 | The place an Env's topology holds for one node; a Service slot goes through the `SlotState`s (`dormant`, `starting`, `ready`, `failed`, `disposing`, `disposed`, `abandoned`); Input, Binding, collection and Entry slots are immediately ready. | `SlotState`, `env.inspect().nodes[]` |
| Reused | 复用 | A node of a child Env that is the parent's visible slot rather than a slot of its own. The placement of every node is `reused`, `new` or `forked`; `explain()` counts them. | `NodePlacement`, `ExplainCounts.reused`, `services.eagerReused` |
| Inherited | 继承 | Said of an Input or a Binding only: the child Env resolves it to the nearest ancestor's provision or choice because its Entry does not declare it. (A Service that comes from the parent is *reused*, not inherited.) | `inputs.inherited`, `parameters.inputsInherited` / `bindingsInherited` |
| Pinned | 固定 | A lineage-unique Family (`uniqueWithin: 'lineage'`) is pinned to the revision and slot it first took in a lineage; descendants cannot diverge from it. The conflict names the pinned revision and slot. | `LINEAGE_UNIQUENESS_CONFLICT.details.pinnedRevision` / `pinnedSlot`, `ForkCause` `pinned-dependency-mismatch` |
| Anchored | 锚定 | An Entry handed to a Service is anchored at the owner Env of that Service's slot; `env.anchor(entry)` anchors one at a chosen Env. The anchor is where the Entry's Env is created. | `AnchoredEntry`, `env.anchor()` |
| Materialize | 物化 | To run a slot's setup and hold the instance. Planning never materializes; `load()` does; `check()` / `explain()` never do. | `ServiceRef.load()`, `loadAll()` |
| Attempt, waiter | 尝试、等待者 | One execution of a setup is an attempt, numbered per slot (`attemptNumber`); each `load()` on it is a waiter with its own wait. | `attemptNumber`, `elapsedMs`, `UnsettledAttemptInspection` |
| Load timeout | 加载超时 | How long one waiter waits on the current attempt before its wait ends with `LOAD_TIMEOUT`. It is the waiter's report, not a verdict on the Service: the attempt keeps running and is *overdue*. | `loadTimeoutMs` (Service option and `limits`), `LOAD_TIMEOUT`, `attempt-overdue`, ledger state `overdue` |
| Abandoned | 放弃 | An attempt the owner's bounded close stopped waiting for. It stays in the ledger until it settles late or its Promise is found unreachable. | `attempt-abandoned`, `env.inspect().abandonedAttempts`, `runtime.inspect().unsettledAttempts`, `runtime-attempts-outstanding` |
| Private, admitted | 私有、接纳 | A Service given to `createRuntime({ services })` is admitted (public); the exact transitive dependencies it pulls in are private to its realm. | `inspect().admittedServices` / `privateServices` |
| Placement | 位置 | See *reused*: where a planned node comes from. | `NodePlacement`, `ExplainedNode.placement` |
| Metadata | 元数据 | Descriptive data on a descriptor, never read by the Runtime. A Service carries two levels: the Family's (`familyMetadata`, `family.metadata`) and the revision's (`revisionMetadata`). | `DescriptorMetadata`, `familyMetadata`, `revisionMetadata` |
